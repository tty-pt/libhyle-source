## 1.0.0

- **First stable release** — the standalone persistence engine for Hyle datasets: dataset definition and registration, record validation, CRUD through pluggable storage drivers, full-text querying, ordered DSV collections, metadata JSON, and JSON state overlays for SSR/WASM hydration. Storage mechanics stay separate from the schemas/query machinery in `libhyle`.
- **Dataset definitions**: `hyle_source_def_t` (`id`, `key_field`, `items_path`, fields, access policy `PUBLIC`/`LOGIN`, list view, storage driver); `hyle_source_register_def` wires a def into the Hyle registry (fields + row maps + FTS), `hyle_source_setup` bootstraps a full dataset in one call.
- **Pluggable storage drivers**: `hyle_source_store_ops_t` — five operations (`scan`, `load`, `put`, `put_field`, `del`). Ship with `hyle_source_store_fs` (per-item directories) and `hyle_source_store_mem` (volatile test stub); `register_def` injects the FS driver by default, or the in-memory one under `HYLE_SOURCE_FLAG_VOLATILE`.
- **Validation**: `hyle_source_validate_row` enforces required fields, int `min`/`max`, `min_length`/`max_length`, and regex `pattern` rules, returning a JSON error list (`HYLE_SOURCE_ERR_VALIDATION`).
- **Query & full-text search**: `hyle_source_query_dataset` — substring search across id + text fields, per-field filters, sort, pagination, with a `__total__` entry.
- **Ordered DSV collections**: `hyle_source_dsv_load`/`_dsv_save` with self-persisting helpers — `_ordered_append_and_save`, `_set_field`, `_remove_and_save`, `_remove_matching`, `_replace_row`, `_find`, `_for_each`, `_sync_form_custom`.
- **Metadata & state overlays**: `hyle_source_meta_read`/`_meta_write` (var/ JSON), `hyle_source_build_state_json`/`_build_state_specs`/`_build_item_json`, and `hyle_source_state_overlay`/`_overlay_from_desc`/`_overlay_array` folding C structs into JSON state (same stride contract as the Bud bridge).
- **Item lifecycle & access helpers**: `hyle_source_item_exists`, `hyle_source_is_creatable` (enforces the def's `PUBLIC`/`LOGIN` access policy), `hyle_source_refresh_row` (reload a row from its storage driver), `hyle_source_for_each_referencing`/`_inv_key_at` iteration over inverse refs, and the `hyle_source_def_to_corm`/`_def_to_meta_fields`/`_def_to_source_fields` def → store mapping helpers.
- **References & options**: `hyle_source_resolve_ref_display_str`, `_get_display_field`, `_get_item_label`, option pools (`_resolve_options`, `_resolve_tokens`, `_normalize_tokens_to_slugs`, `_get_enum_options`) feeding picker dropdowns, plus inverse-reference bookkeeping (`hyle_source_find_referencing`, `hyle_source_inv_keys`, `_clear_inverse_refs`).
- **Forms & files**: `hyle_source_parse_row_data_custom` with `hyle_field_getter_fn`/`hyle_multi_field_getter_fn` callbacks; `hyle_source_is_safe_id`, `_slurp_file`, `_write_file`, `_remove_path_recursive`, `_resolve_doc_root`.
- **Picker DTO ownership**: canonical home of the picker presentation types (`hyle_option_t`, `hyle_picker_desc_t`, `hyle_picker_entry_t`, `hyle_picker_view_t`, `hyle_picker_buffer_t`) in `<hyle-source/picker.h>`.
- **Dependencies**: `libhyle`, `libcorm`, `libstoma` (FTS), `json-c` — no framework, no network, no UI.
